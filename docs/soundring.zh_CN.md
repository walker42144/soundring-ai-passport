# 声环 SoundRing：AI Passport 上的 Spotify 遥控器

SoundRing 把 AI Passport 变成 Spotify 遥控器：显示播放状态并发送 Web API 指令。声音始终由手机、
电脑或其他 Spotify Connect 设备播放；本固件不解码、不缓存、不下载音频。

## 页面与按键

每个页面是一屏 240 × 320 竖屏，黑底 + Spotify 绿色强调。

| 页面 | 上 / 下 | 长按上 / 下 | 确定 | 长按确定 |
| --- | --- | --- | --- | --- |
| 首页 | 上一首 / 下一首 | 音量 ∓5 | 播放 / 暂停 | 菜单 |
| 列表 | 移动 | 上一页 / 下一页 | 打开 / 播放 / 切换 / 修改 | 返回 |
| 音量 / 进度 | ±5% / ±10 秒 | ±10% / ±30 秒 | 提交 | 取消并返回 |
| 亮度 | ±10% | ±20% | 保存 | 取消并返回 |
| 配对 / 说明 | — | — | — | 返回 |

首页包含封面、歌名（两行）、歌手、播放设备、本地平滑推进并与服务器校准的进度条、随机/循环/音量
状态，以及上一首/播放/下一首。

### 首页页脚提示

页脚不再恒定显示按键提示，而是先说明当前阻塞点：

| 状态 | 页脚 |
| --- | --- |
| 未授权 | `未授权：设置 → 电脑配对` |
| 离线 | `离线：检查 Wi-Fi 连接` |
| 等待校时 | `校时中：请稍候` |
| 已授权但无活跃设备 | `无活跃设备：请先在手机播放` |
| 一切就绪 | `确定 播放/暂停 · 长按 菜单` |

### 菜单（首页长按确定）

单屏滚动的 6 行窗口内共 13 项：歌单、队列预览、最近播放、播放设备、音量、进度、**随机播放**、
**循环模式**、收藏当前、设置、使用说明、立即息屏、返回首页。

随机与循环是一次按键即可切换的开关，副标题显示服务器上的实时状态：

* `随机播放` — 副标题 `开` / `关`；按确定取反，250ms 后自动轮询刷新状态。
* `循环模式` — 副标题 `关` / `列表` / `单曲`；按确定按 `off → context → track → off` 推进。

每次切换都有 toast 确认（`随机已开`、`循环：列表` 等）。指令仍然走统一的 800ms 门控，连点会被
拒绝并提示 `操作太快，请稍候`，不会排队堆积。

## 结构

| 文件 | 职责 |
| --- | --- |
| `main/sr_app.c` | 页面栈、按键策略、工作线程、轮询与退避、UI tick、配对回调 |
| `main/sr_ui.c` | LVGL 渲染与设计 token（黑底、`#1DB954`、14/20/28 px） |
| `main/sr_spotify.c` | Web API、令牌刷新、429 分类、2026 歌单/收藏接口 |
| `main/sr_http.c` | 有界 HTTPS 请求、根证书校验、`Retry-After`、1KB 错误体 |
| `main/sr_cover.c` | 24 KB 下载上限、≤120 px JPEG 解码、SPIFFS 缓存（8 个 / 512 KB） |
| `main/sr_pair.c` | USB 串口配对：PBKDF2-HMAC-SHA256 + AES-256-GCM |
| `main/sr_policy.c`、`sr_progress.c`、`sr_text.c`、`sr_playback.c` | 可主机测试的纯逻辑 |
| `main/fonts/` | 生成的 Noto Sans SC 子集（14/20/28 px），OFL 1.1 |

网络请求集中在一个工作线程，且请求期间不持状态锁，按键不会被轮询阻塞。所有 LVGL 访问都在
`bsp_lvgl_lock()` 内。

工作线程还负责首页的**本地 UI tick**：播放中每秒重绘一次文本与进度条，暂停时每 5 秒一次。tick
不发任何请求、也不影响轮询计划，因此进度条在两次（更省资源的）网络轮询之间也能平滑推进。

## 轮询、耗电与限流

| `poll_fast` | 播放中 | 暂停 | 说明 |
| --- | --- | --- | --- |
| 标准（`1`） | 3000ms | 6000ms | 需手动切换，进度更顺 |
| 省电（`0`，**默认**） | 5000ms | 15000ms | 电池设备的默认档 |

参数原值为手表版的 `1000` / `1500` ms。AI Passport 是 ESP32-C3、无 PSRAM、单核，而
`sr_http.c` 每次请求都新建连接（`keep_alive_enable = false`），也就是每次轮询都要完整做一遍
TLS 握手。每秒一次轮询会让握手长期占据 CPU 并显著耗电，对电池设备不可接受，因此标准档改为
3000/6000。读取失败仍按 2s → 4s → 8s → 16s → 32s 指数退避，指令提交仍保持 800ms 门控。

HTTP 429 被分成两类，因为两者的恢复时间差两个数量级：

| 判据 | 封禁时长 | 用户文案 |
| --- | --- | --- |
| `error.reason = QUOTA_EXCEEDED` | 900 秒（15 分钟） | `开发模式配额已用尽，15 分钟后重试` |
| 其它 429 | `Retry-After`（1 秒…24 小时，缺省 30 秒） | `Spotify 限流，稍后自动重试` |

封禁期内工作线程直接停止轮询：既不会每两秒撞一次墙，也不会反复弹同一条提示。

## 收藏（library）接口

`uris` 是 **query** 参数而不是 JSON 请求体，成功时返回 `200` 且无响应体：

* 收藏：`PUT /me/library?uris=<url_encode(uri)>`，不带请求体
* 取消收藏：`DELETE /me/library?uris=<url_encode(uri)>`
* 单次最多 40 个 URI；本固件每次都只传当前曲目的一个 URI

## 列表

在「歌单曲目」「最近播放」「队列预览」中，`uri` 与当前播放曲目一致的行的副标题前会加
`播放中 · ` 前缀。选中项的绿色高亮逻辑与此独立、保持不变。这里用纯文字而不是 ▶ 之类符号，
因为字体子集只包含 `main/` 里出现过的字符。

## 首次配置

1. 设备上进入 **设置 → 电脑配对**，屏幕显示 8 位配对码（10 分钟有效，5 次错误结束）。
2. USB 连接电脑，在 Windows PowerShell 7+ 运行 `tools/soundring-setup.ps1 -ClientId <id>`。
3. 工具在本机 用户自行填写的本机回调地址 完成 PKCE，并把 Wi-Fi 与令牌加密写入设备，全程
   不打印、不落盘。

权限范围：`user-read-playback-state user-modify-playback-state playlist-read-private
playlist-read-collaborative user-read-recently-played user-library-read user-library-modify`。
任何环节都不使用 Client Secret。

## 息屏行为

息屏分两级，计时从最后一次按键开始：

| 阶段 | 触发条件 | 实际动作 |
| --- | --- | --- |
| 变暗 | 闲置达到设定时长（30 / 60 / 120 秒，可关闭） | 背光降到 10% |
| 息屏 | 再闲置 30 秒 | 先停面板扫描（`esp_lcd_panel_disp_on_off(false)`），再关背光到 0 |

顺序上先关显示再关背光，避免背光断开的瞬间闪出一帧白场。ST7789 关闭显示时会保留 GRAM，因此唤醒
路径只需重新打开扫描、强制整体重建并重绘所有控件。

息屏**不进 deep sleep**：deep sleep 会断开 Wi-Fi 关联、丢失 SNTP 校时，每次唤醒都要重新联网并重新
校时，才可能发出第一个请求。这里改为关掉面板、让射频、LVGL 与配对任务继续运行——唤醒是即时的，
代价是息屏期间 Wi-Fi 仍保持关联，待机仍有连接功耗。

息屏期间同时停止重绘与轮询：渲染入口直接返回，`poll_due_locked()` 也拒绝发请求，所以黑屏时不会有
任何 TLS 握手。工作线程改为 5 秒醒一次，只服务于配对回调与息屏计时；唤醒由按键回调直接处理，不依赖
这个周期。

任意键唤醒。唤醒的那一次按键被用于点亮屏幕，不会同时触发播放/暂停或移动光标。菜单里的「立即息屏」
与 **设置 → 立即息屏** 会立刻执行同样的动作。

## 存储与安全边界

令牌以明文保存在 NVS；本板配置未启用 Flash/NVS 加密。能读取 Flash 的人可以取出令牌，这比平台
Keystore 弱，不能对外声称“无法读取”。处置设备前请在 Spotify 账号中撤销应用授权，并在设备上执行
**设置 → 清除授权**。


## 限制

- 无 OTA，升级需重新刷写。
- 超过 24 KB 或非 baseline JPEG 的封面降级为占位图。
- 封面解码到 120 px 正好等于显示区；Wi-Fi 常驻后内部堆还要留出 25–30 KB 连续空间给 TLS 握手。
- 开发模式应用只能读取本人拥有或协作的歌单。
- 开发模式配额用尽后轮询会停止 15 分钟，只能等待或换用有生产配额的应用。
- 在声明“实机可用”之前，必须完成真机验证：Wi-Fi、TLS、授权、按键与控件、内存余量。
